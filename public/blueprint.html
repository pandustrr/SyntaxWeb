1. Kompatibilitas Multi-Platform (Mac & iOS)

1.1. Status Teknis Repositori Saat Ini

Aplikasi Flutter syntax_pos_flutter sudah memiliki folder runner bawaan /ios dan /macos di dalam repositori. Kode aplikasi 100% menggunakan Flutter SDK standar yang bersifat cross-platform.

STATUS: BISA 100% DIJALANKAN DI MAC & iOS

Seluruh dependensi pada pubspec.yaml sudah mendukung penuh macOS & iOS:

  • dio: Berjalan native via NSURLSession Apple.
  • flutter_riverpod: State management murni Dart (semua platform).
  • flutter_secure_storage: Otomatis tersambung ke Apple Keychain (aman & terenkripsi).
  • shared_preferences: Menggunakan NSUserDefaults bawaan iOS/macOS.
  • google_fonts & go_router: Didukung 100%.

1.2. Kebutuhan Infrastruktur & Syarat Apple

  • Alat Kompilasi (Build Tool): Wajib menggunakan komputer bersistem operasi macOS (MacBook / Mac Mini / iMac) dengan aplikasi Xcode dan CocoaPods terinstal.
  • Uji Coba Langsung ke iPhone/iPad Fisik (Gratis): Cukup hubungkan perangkat fisik via kabel ke Mac menggunakan Apple ID biasa (berlaku masa aktif 7 hari sebelum ditandatangani ulang).
  • Distribusi Produksi (App Store / TestFlight): Membutuhkan akun Apple Developer Program ($99/tahun) untuk mengirim aplikasi ke TestFlight (pengujian nirkabel tanpa colok kabel) atau rilis publik App Store.
  • Khusus Mac (macOS App): Bisa diekspor langsung sebagai file .dmg atau .app tanpa melalui Mac App Store (cukup proses notarization mandiri).

1.3. Catatan Khusus Printer Thermal di iPad / iPhone

PENTING: Sistem operasi iOS Apple membatasi akses kabel USB data mentah (raw serial) kecuali produsen memiliki chip lisensi Apple MFi. Oleh karena itu, standar industri printer POS untuk iPad/iPhone adalah:

  • Printer Bluetooth (BLE - Bluetooth Low Energy).
  • Printer Jaringan / Wi-Fi LAN (TCP/IP port 9100) terhubung satu router/hub WiFi kafe.

2. Solusi Tampilan Responsif (Adaptive Layout)

2.1. Penjelasan Istilah Permasalahan UI Saat Ini

  1. Kenapa Sidebar dan Keranjang Menghilang di Mode Potret HP?
    Istilah Teknis: Hidden Drawer Fallback without Trigger & Omitted Component.
    Akar Masalah: Pada file pos_screen.dart, breakpoint ditentukan isMobile = screenWidth < 768. Jika layar HP potret (<768px), sidebar disembunyikan ke dalam Drawer, namun pada bar atas tidak dibuatkan tombol Menu/Hamburger untuk membukanya. Sementara itu, panel keranjang kanan dimatikan dengan kode: if (!isMobile) const CartPanel(...) tanpa disediakan tombol alternatif di layar HP.
  2. Kenapa di Mode Landscape Elemen Bertumpuk / Rusak?
    Istilah Teknis: RenderFlex Overflow (layar garis hitam-kuning) akibat Unconstrained Viewport Height Thrashing.
    Akar Masalah: Pada posisi miring (landscape), lebar layar memang bertambah (~800px), tetapi tinggi layar sangat sempit (hanya 360px - 400px). Widget vertikal bertumpuk (Shift Bar 38px + Kategori 50px + Search 38px + Grid Kartu Menu + Footer Total Keranjang 180px) membutuhkan ruang tinggi lebih dari 550px, sehingga menabrak batas layar dan memicu overflow.

Fitur SuperAdmin di Website:

  • Manajemen Kafe (Multi-Tenant Management): Daftar seluruh kafe terdaftar, status (Pending, Active, Suspended), nama owner, kontak WhatsApp, dan paket lisensi.
  • Tambah Akun & Kafe Manual: SuperAdmin dapat membuatkan profil kafe baru langsung dari portal beserta akun Owner perdana.
  • Suspend / Nonaktifkan Kafe: Jika status kafe diubah menjadi SUSPENDED, seluruh kasir dan staf kafe tersebut otomatis terkunci dan tidak dapat melakukan transaksi.
  • Monitoring Server & API Global: Memantau kesehatan server, latensi query database, dan volume transaksi gabungan seluruh kafe.
  • Impersonation (Masuk Sebagai Kafe): Mode inspeksi untuk membantu kendala teknis kafe tertentu secara read-only.

5. Pengelolaan Menu Berfoto & Profil Kafe

5.1. Fitur Produk & Menu Lengkap

  • Foto Menu: Dukungan upload foto dari kamera langsung atau galeri, otomatis dikompresi ke format ringan (WebP/JPEG, maks 250 KB) disimpan di folder publik server.
  • Data Menu: Nama Produk, Kategori, SKU/Barcode, Deskripsi, Harga Jual, Harga Modal (COGS).
  • Varian / Modifiers: Ukuran (Regular, Large), Jenis Sajian (Hot, Ice), Level Gula/Pedas beserta penyesuaian harga tambahannya.
  • Integrasi Resep Bahan Baku (BOM - Bill of Materials): 1 porsi menu dapat ditautkan dengan bahan baku (misal: 1 porsi Kopi Susu = 18 gr Biji Kopi + 120 ml Susu Segar + 25 ml Gula Aren). Stok bahan baku otomatis terpotong saat transaksi selesai.

5.2. Fitur Profil Kafe Lengkap

  • Upload Logo Kafe dan Gambar Header.
  • Informasi Bisnis: Nama Brand, Slogan, Alamat Lengkap, Kota, Nomor Telepon, Jam Operasional.
  • Pengaturan Meja: Jumlah dan penamaan denah meja cafe.
  • Metode Pembayaran: Rekening Bank, Akun QRIS Statis / Dinamis.

6. Keamanan & Penyembunyian Server API

  • Penyembunyian Total pada Antarmuka Kafe: Seluruh label teknis seperti API URL, Server Connection, atau pemilih server dihapus 100% dari antarmuka login dan dashboard kasir. Aplikasi kasir otomatis terhubung ke endpoint resmi: https://syntaxweb.id/api/pos.
  • Mode Teknisi Rahasia (Secret Maintenance Mode): Jika staf teknis membutuhkan inspeksi jaringan di lokasi kafe, teknisi cukup menekan logo SYNTAX POS sebanyak 7 kali berturut-turut pada layar login, lalu memasukkan PIN SuperAdmin. Barulah muncul panel status jaringan, tes ping, dan log sinkronisasi lokal.
  • Monitoring Server Hanya di Portal SuperAdmin: Seluruh grafik kesehatan server, error log, dan pemantauan API hanya bisa diakses oleh SuperAdmin di web melalui /admin/system.

7. Rekomendasi Role, Permission & Pengelompokan Menu

Prinsip: Tidak ada fitur yang dihilangkan dari kode yang sudah ada saat ini. Seluruh 11 modul eksisting tetap dipertahankan dan dikelompokkan sesuai fungsi jabatan.

PEMBAGIAN 5 TINGKATAN ROLE
  1. SUPER_ADMIN Pemilik Platform Syntax: Berada di Web Admin. Mengelola lisensi kafe, persetujuan pendaftaran kafe baru, monitoring server, dan manajemen akun tingkat tinggi.
  2. OWNER Pemilik Kafe: Memiliki hak akses PENUH atas seluruh 11 modul kafe miliknya (Laporan Laba, Keuangan, Menu, Resep, CRM, Promo, Pegawai, Pengaturan Struk).
  3. MANAGER Manajer Operasional Kafe: Mengawasi operasional harian, mengelola bahan baku & stok masuk, mengelola member CRM & voucher, memantau kinerja kasir, dan memberikan otorisasi pembatalan nota (void/refund).
  4. CASHIER Kasir: Fokus pada kecepatan pelayanan kasir (POS), buka/tutup shift laci kasir, pemilihan meja pelanggan, input pesanan, dan pencarian member CRM saat transaksi.
  5. KITCHEN_BAR Kru Dapur / Barista: Menggunakan layar Kitchen Display System (KDS) untuk melihat daftar tiket pesanan, mengubah status memasak, dan menandai pesanan selesai disajikan.

10. Skema Basis Data & Tahapan Eksekusi

10.1. Penyesuaian Skema Prisma (schema.prisma)

// Status Persetujuan Kafe
enum BusinessStatus {
  PENDING_APPROVAL
  ACTIVE
  SUSPENDED
  REJECTED
}

// 5 Tingkatan Role Pengguna
enum UserRole {
  SUPER_ADMIN
  OWNER
  MANAGER
  CASHIER
  KITCHEN_BAR
}

// Model Tenant Bisnis Kafe
model PosBusiness {
  id                Int            @id @default(autoincrement())
  name              String
  slug              String         @unique
  address           String?        @db.Text
  phone             String?
  logoUrl           String?
  status            BusinessStatus @default(PENDING_APPROVAL)
  
  // Konfigurasi Struk Dinamis
  receiptHeader     String?        @db.Text
  receiptNotes      String?        @db.Text
  receiptFooter     String?        @db.Text
  receiptPaperSize  String         @default("58mm")
  showLogoOnReceipt Boolean        @default(true)
  showWifiOnReceipt Boolean        @default(false)
  wifiPassword      String?
  taxPercent        Decimal        @default(10.00) @db.Decimal(5, 2)
  isTaxInclusive    Boolean        @default(false)
  servicePercent    Decimal        @default(0.00) @db.Decimal(5, 2)

  createdAt         DateTime       @default(now())
  updatedAt         DateTime       @updatedAt

  users             User[]
  categories        PosCategory[]
  products          PosProduct[]
  materials         PosMaterial[]
  tables            PosCafeTable[]
  customers         PosCustomer[]  // CRM Tetap Ada & Terhubung
  promotions        PosPromotion[] // Promo & Voucher
  shifts            PosShift[]
  orders            PosOrder[]

  @@map("pos_businesses")
}
